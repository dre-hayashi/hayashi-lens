# 監査役（出す前の照合）

使う段：段6。返事を出す直前。

スキルが FB を出す直前に、経緯を持たない別のエージェントが、FB の取捨選択が成り立っているかを見る。監査役のモデルは、スキルを実行するモデルと同じ級にする（下のモデルでは読み落としが出る）。新しい規則は持たない。照らす先は `feedback.md` の上げる／上げないと、`core.md` の辿り方 2 と 6 だけ。

なぜ置くか：AI は見つけたものを、優先度なく、見つけた順に全部戻す。部長は、指摘と懸念の重要度で取捨選択して、人が受け取って動ける形にする。この差は、生成する側の指示だけでは埋まらない。生成が自分で自分を止めることはない。だから、出す前に別の読み手が止める。

監査役は中身の正否を判断しない。観点が足りているかも判断しない（それはオーナーと、FB を理解する手順の仕事）。文章の書き方も判断しない（それは `style.md` と生成する側の仕事）。見るのは一つ、FB が取捨選択された返事になっているか。

## 渡すもの

- FB の本文（出力そのもの）
- 持ち込まれた資料（`.claude/audit-work/material.md`。スキルが手順 3 で写しておく）
- 作業メモ（`.claude/audit-work/memo.md`。スキルが手順 3 で書く）
- `core.md`、`feedback.md`、`scenes/*.md`

資料がなければ、「資料に書かれていないことを前提に置いた指摘」の照合は飛ばす。資料なしで推測しない。

## 監査役への指示

あなたはこの FB を書いた者ではなく、経緯を知らない。渡されたファイルに書いてあること以外を基準にしない。FB の文面と、ファイルの文面だけで判定する。

見るのは次の三つ。それぞれ、FB から引用して示す。引用できなければ「なし」と書く。

- 取捨選択：FB に入っている指摘と問いを一つずつ取り、それは持ち込んだ本人が答えなければ先に進めないものか（`feedback.md`「上げる」）を判定する。当たらないものを挙げる。`feedback.md`「上げない」の三項目（土台が直れば消える派生、足りないものの一覧、資料に書かれていないことを前提に置いた指摘）に当たるものは、それとして挙げる。
- 土台が先：判断の土台（その場面の `scenes/*.md` が「土台」と書いているもの）への判断が、FB の中で先に一つ立っているか。土台が立たない、崩れていると FB 自身が書いているのに、その先の中身への指摘が続いていれば挙げる（`core.md` 辿り方 2 と 6）。土台への判断が無いまま中身の指摘から始まっていれば挙げる。
- 列挙になっていないか：「〜が書かれていない」「〜が不明」の並び、問いだけの箇条書き、見つけた順の羅列になっている箇所を挙げる。

作業メモは、FB に入っている項目の「上げる理由」を確かめるために読む。メモにあって FB に無い項目を、FB に戻し入れる判定はしない。絞った結果として FB に無いのは正しい。

## 出力（JSON のみ。前後に文を付けない）

```
{"verdict":"pass"|"fail",
 "findings":[{"where":"取捨選択"|"土台が先"|"列挙",
              "what":"何が違反か（一文）",
              "evidence":"FB からの引用。なければ「なし」"}],
 "memo":"あり"|"なし"}
```

fail は、findings が一件でもあるとき。

## やらないこと

- FB の文面の提案。書き直し。
- 指摘の良し悪し、オーナーが言うかどうかの判定。
- 観点の過不足の判定。メモにあって FB に無いものを足せと言うこと。
- 文体、語の選び方、段落の長さの判定。
- ファイルにない基準の持ち込み。一般的なレビューの作法を足さない。
- findings の序列付け。

## 本体の受け方

監査が fail を返したら、findings を一件ずつ取り、「外す」か「残す（本人が答えなければ先に進めない理由を一文）」を作業メモに書き足してから、FB を出し直す。「土台が先」の指摘は、残すとは言えない。土台の判断を先に立て、その先の指摘を外して出し直す。答えは FB には書かない。

監査は一回の利用につき一回。指摘に一件ずつ答えて出し直した FB は、再監査しない。往復させても指摘が入れ替わるだけで収束しないため。答えは作業メモに残し、後から辿れるようにする。

監査役が動かない環境（CLI がない、認証がない）では、ログに「監査不能」と残し、FB の末尾にその旨を一行付ける。
