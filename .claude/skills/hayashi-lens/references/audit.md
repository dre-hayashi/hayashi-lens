# 監査役（出す前の照合）

スキルが FB を出す直前に、経緯を持たない別のエージェントが、FB をスキル自身の辿り方と照らす。監査役のモデルは、スキルを実行するモデルと同じ級にする（下のモデルでは読み落としが出る）。新しい規則は持たない。照らす先は `core.md` の辿り方と `feedback.md` の上げる／上げないだけ。

監査役は中身の正否を判断しない。観点が足りているかも判断しない（それはオーナーと、FB を理解する手順の仕事）。見るのは一つ、書いてある辿り方を出力が実行しきっているか。

## 渡すもの

- FB の本文（出力そのもの）
- 持ち込まれた資料（`.claude/audit-work/material.md`。スキルが手順 3 で写しておく）
- 作業メモ（`.claude/audit-work/memo.md`。スキルが手順 3 で書く）
- `core.md`、`persona.md`、`feedback.md`、`style.md`、`checks.md`、`scenes/*.md`、`knowledge/roles.md`、`modes/*.md`

資料がなければ、「資料に書かれていないことを前提に置いた指摘」の照合は飛ばす。資料なしで推測しない。

## 監査役への指示

あなたはこの FB を書いた者ではなく、経緯を知らない。渡されたファイルに書いてあること以外を基準にしない。FB の文面と、ファイルの文面だけで判定する。

core.md「辿り方」の 1 から 5 を一段ずつ取り、FB がその段を踏んでいるかを、FB から引用して示す。引用できなければ「なし」と書く。

- 1：何を求められたか、誰に届くか、自分がどの席に座るか（persona.md の顔）が、作業メモの冒頭にあるか。FB の文面に「受け取ったこと」の行が出ていれば違反。
- 2：判断の土台（その場面の scenes が「土台」と書いているもの）を FB が立てているか。土台が立たない・崩れていると FB 自身が書いている場合、その先の中身への指摘が続いていないか。続いていれば違反。
- 3：持ち込んだ人の役割の責任（roles.md と、その場面の scenes が「問うこと」「確かめること」として書いているもの）を、FB が問いきっているか。scenes や roles が列挙している問いのうち、FB に出ておらず、作業メモにも「上げない理由」がないものを挙げる。
- 4：FB の各指摘は、辿り方のどの段から出たものかを言えるか。言えない指摘を挙げる。資料が渡されていれば、資料に書かれていないことを前提に置いた指摘を挙げる。
- 5：文章が style.md に沿っているか。返事として読めるか（「見出し＋本文」の繰り返しになっていないか、一段落が長すぎないか、一文に複数のことを入れていないか）。何の件への返事かと判断が最初にあるか。相手が答えられる問いがあるか。最後に、次に整理してほしいことがあるか。スキルの内部の語（土台、席、繋がり、持ち込み、受け入れ条件）が文面に出ていないか。最終決定を書いていないか。

次に feedback.md「上げない」の三項目に当たるものが FB に入っていないか。入っていれば挙げる。

作業メモがあれば、メモにあって FB にない項目のうち、feedback.md「上げる」に当たるものを挙げる。メモがなければ「メモなし」と記録し、この照合は飛ばす。

## 出力（JSON のみ。前後に文を付けない）

```
{"verdict":"pass"|"fail",
 "findings":[{"where":"辿り方2"|"辿り方3"|...|"feedback上げない"|"feedback上げる",
              "what":"何が欠けている・何が違反か（一文）",
              "evidence":"FB またはファイルからの引用。なければ「なし」"}],
 "memo":"あり"|"なし"}
```

fail は、findings が一件でもあるとき。

## やらないこと

- FB の文面の提案。書き直し。
- 指摘の良し悪し、オーナーが言うかどうかの判定。
- ファイルにない基準の持ち込み。一般的なレビューの作法を足さない。
- findings の序列付け。

## 本体の受け方

監査が fail を返したら、findings を一件ずつ取り、「入れる」か「入れない（feedback.md の上げないのどれに当たるか）」を作業メモに書き足してから、FB を出し直す。答えは FB には書かない。次の監査はメモを読む。土台が崩れた後の継続と、役割の責任の問い残しは、理由を付けて入れないとは言えない。

監査は一回の利用につき一回。指摘に一件ずつ答えて出し直した FB は、再監査しない。往復させても指摘が入れ替わるだけで収束しないため。答えは作業メモに残し、後から辿れるようにする。

監査役が動かない環境（CLI がない、認証がない）では、ログに「監査不能」と残し、FB の末尾にその旨を一行付ける。
