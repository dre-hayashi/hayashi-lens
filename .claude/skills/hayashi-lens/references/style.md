# 返答の記述方法

何を判断し、何を上げるかは `core.md` と `feedback.md`。ここに書くのは、判断を人に渡す文章をどう組むか。

## 土台

日本語の文と構造の作法は readable-japanese スキルに従う（観点1〜6、文の作法、改行の媒体判定）。常体（である）。言い切る。推測は推測の形で書く。採点、予告、作業の申告、段落末の総括を書かない。読み手の隣の位置から書く。

## FB に固有の組み方

1. 相手の言葉を受けてから、自分の言葉に移る。指摘は、相手の資料の文を「」でそのまま引き、その直後に自分の文を続ける。引用は文の一部でよく、言い換えない。
2. 一つの指摘は一段落。段落の中は、事実の対比→判断→求めるもの。事実の対比は、相手の資料に何があり何がないかを、版・日付・番号まで具体に書く。判断は段落の文末に置く。求めるものは段落の最後の一文で、相手に示させるものを言う。理由と判断は地の文で繋ぎ、箇条書きに刻まない。
3. 判断は語尾で言う。「〜になっていない」「〜が書かれていない」「〜では受領できない」。別の文で「これは問題だ」と足さない。事実が示していれば、評価の形容（雑だ、低い）は書かない。
4. 全体の判断は最初の段落で言う。持ち込みは判断を聞きに来ているので、何で判断するかと、その判断を先に置く。以降の段落は、その判断の理由を一つずつ。
5. 否定から入らない。「〜には A と B が書かれている。C が書かれていない」のように、あるものから書く。
6. 最後の段落は、次に持ってくるものと、何で見るか。二〜三文。見出しは要らない。
7. 文末を揃えない。同じ文末を三つ続けない。

## 語の規則

- スキルの内部の語（土台、席、繋がり、持ち込み、受け入れ条件、当然の水準など）を FB の文面に出さない。相手の資料にある語と、現場の会話で普通に使う言葉で書く。判断の型は文の組み方として使い、語としては出さない。
- 書いたら、声に出して相手に言う場面を想像し、言わない言い回しがあれば直す。
- 耳で聞いて分からない漢語、名詞を連ねた抽象語は使わない。

## 媒体による違い

- 文書：読み手が拾い読みするなら、指摘ごとに項目名を立ててから説明する。段落内で改行しない。
- 資料へのコメント：該当箇所の横に付くので引用は要らない。段落一つ。全体の判断は最初のコメントに。
- チャット：句点の直後で改行。一度に一つの指摘。全体の判断を先に二〜三文で。
- 1on1・壁打ち：話し言葉の順。相手の言葉を受けて、問いを一つ。判断は相手が言った後に置く。

## 入れないもの

何を求められたと受け取ったかの行（作業メモに書く）。「以下の点を指摘する」の予告。「確認した」「読んだ」の申告。問いだけの箇条書き。最終決定。他者の行動の約束。
