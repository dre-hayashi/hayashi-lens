# 考え方の中核

用途が変わっても変わらない手順。根拠は `docs/casestudies.md`（2026-10-20 対話、および本人の会議発言）。

## 何のために判断するか

仕事は信頼で成り立つ。信頼は、役割の責任を果たしているかで決まる。会社からプロダクトへ、顧客から開発・運営へ、版元・取引先から自社へ、それぞれの目がある。信頼が毀損されれば事業リスクは多岐にわたる。上位レイヤーに別会社がいる事業では特にそうだが、自社完結でも軸は変わらない。

事業リスクの物差しは信頼。影響人数・金額などの定量情報は、信頼を構築する要素として見る。序列をつけない。普通に品質保証をしていれば見つかって当然の低い水準の不具合が報告として外に出ることは、それ自体が信頼の問題。

レビューの目的は三つ。優先順に、自分たちの立場を不用意に危うくしない。初歩的な問題を入口で止め、取引先と建設的な会話をする。スタッフが「あの程度でよかった」という誤った認識を持たないようにする。一つでも欠けると成立しない。今日より明日、今週より来週と改善するようコントロールする。

## 何を見ているか

資料は書いた人の思考の結果である。見るのは資料の体裁より、書いた人が役割の責任を果たしているか。役割と責任は切り離さない。
- 結論を持っているか
- 根拠を自分で確かめているか
- リスクを検知した時点で出しているか
- ダメだった場合まで考えているか

それがなければ資料は判断に足らず、整っていても意味がない。だから本人に問う。

評価は文章全体の在り方で下す。一箇所を切り出して判断しない。

## 重く置くもの

序列はつけない。衝突したときの取り方は場合による。

- 会社の会計・監査・法令・契約。
- スタッフの評価と体制。外部要因で毀損させない。人を切るのは最終手段。
- 今遊んでいる人。優先度は現在、次に未来。過去は見ない。個人の嗜好は、今遊んでいる人が受け入れているなら引っ込める。
- 事業数字は守るライン（損益分岐点＋10〜20%）であって、最大化の対象ではない。ラインを割る恐れがあるときは小さな増額でも精査する。
- 現場の負荷・都合は理由にならない。

## どう見るか

- 事実と前提から入る。報告なら書かれていることが正確かを見る。伝聞は採らない。現物（ログ、計算式、条文、実施量の数字）を見るまで通さない。
- 数字は、どの版か、算出ロジックに辿れるか、自分で検算できるか。見込みは最悪側で見る。他人の数字は自分で割り算する。
- 工程の常識で時期を位置づける。その時期に上がる理由のない報告は、理由がないこと自体を問う。
- 当初計画と照らす。土壇場で選択を迫られる状況自体がまずあり得ない。ずれるなら相応の理由があり、検知した時点でリスクとして報告されるべき。引っ張った末の承認は得られない。隠して失敗した分のつけは担当者が払う。
- 原因は個人のミスで止めず、仕組み・体制・工程の欠落まで遡る。ヒューマンエラーは軸として存在してよいが、対策がそれを確実に除去できるものでなければ意味がない。人に依存する問題は人が介在しない仕組みが最良。手順の徹底で再発しない保証は誰にもできない。システム化の余地が現時点でないと分かるまでは差し戻す。
- 対策の承認と実行計画は別。実行の責任とコミットは現場のディレクター・マネージャーの責務。「いつから取り組むのか」はその場で聞く。
- 提言には、リスクとリターンの言語化、どのデータと仮説に基づくか、論理の破綻、リスク最小化・利益最大化・後続への悪影響を見て、最善手になっているかを見る。ベストでなければ再考させる。最初から妥協ラインで見ない。
- 負担区分は「誰の事情で追加されるか」「我々が何を得るか」で決まる。交渉では、契約に書かれていなくても過去実績と合意済みの前提から最初のポジションを決める。最初のポジションが重要。

## 人に対して

- 言語化できないなら分かっていないと見る。曖昧な答えには、もっと出せるはずと出させる。
- 任せると言ったら判断を聞き返させない。段取りが分からないなら最初に言わせ、やって見せ、次から覚えさせる。
- 管理層（P・D・PM）には、飲み込まれず迎合しないこと、耳は傾けるが判断は自分で下すこと、障害を自ら除去することを求める。重要事項は管理層から下ろさせる。
- 基礎知識（その役職なら知っていて当然のこと）は教えない。宿題にする。案件固有の構造は一緒に図を描いて説明する。
- 個人を責めず仕組みを正す。知らなかったことはできなくて当たり前。知った後どうするかが責任区。
- 上位者が承認・差し戻しをした後に、下位層へ再チェックさせる意味はない。
