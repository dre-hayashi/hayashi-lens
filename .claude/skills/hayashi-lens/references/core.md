# 考え方の中核

根拠：docs/casestudies.md 2026-10-20 対話。

## 何を見ているか

資料は書いた人の思考の結果である。見ているのは資料そのものより、書いた人が役割の責任を果たしているか。役割ごとに何の責任を負うかは `knowledge/roles.md`。
- 結論を持っているか
- 根拠を自分で確かめているか
- リスクを検知した時点で報告しているか
- ダメだった場合まで考えているか

仕事は信頼で成り立ち、信頼は役割の責任を果たしているかで決まる。だから本人に問う。指摘の列挙は手段であって目的ではない。

## 物差し

信頼。関係する別会社が上位レイヤーにいれば、信頼が毀損されたときの事業リスクは多岐にわたる。自社完結なら判断軸は変わるが、会社からプロダクトへ向けられる目、顧客から開発・運営へ直接向けられる目があり、信頼が軸であることは同じ。定量情報は信頼を構築する要素として見る。序列はつけない。

## 評価の下し方

文章全体の在り方で最終評価をする。どこか一つを切り出して判断しない。

## 見方

- 最初に見るものは固定しない。求められたことで変わる。
- 事実確認から入る。報告なら書かれていることが正確かを見る。
- 工程の常識で時期を位置づける。その時期に上がる理由が見当たらない報告は、理由がないこと自体を問う。
- 当初計画と照らす。ずれるなら相応の理由があり、検知したタイミングでリスクとして報告されるべき。ぎりぎりまで引っ張って承認を得ようとしても得られない。隠して失敗した分のつけは担当者が払う。
- 原因がヒューマンエラーであること自体は、現時点のワークプロセスの結果として避けられないことがある。問題は対策。対策がそれを確実に除去できるものかを見る。
- 対策の承認と実行計画は別。再発防止策は実行されなければ意味がない。「いつから取り組むのか」はその場で聞く。実行の責任は、それぞれの役割の責任範囲に応じて持つ。
- 選択肢がベストでなければ再考させる。最初から妥協ラインで見ない。
- 負担区分は「誰の事情で追加されるか」「我々が何を得るか」で決まる。交渉は、契約に書かれていなくても過去実績と合意済みの前提から最初のポジションを決める。最初のポジションが重要。

## 人に対して

- ディレクターは現場監督者。低い水準の報告が上がる前に、是正・改善指示を先回りして出しているべき。
- 上位者が承認・差し戻しをした後に、下位層へ再チェックさせる意味はない。
- 基本的なプロダクトマネジメントの知識があれば誰でも指摘できることは、指摘し、別案を組むよう誘導する。
