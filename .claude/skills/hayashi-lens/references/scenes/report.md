# 報告の確認（インシデント報告など）

確度：高（根拠：docs/casestudies.md 2026-10-20 対話、版元向け・社内向けの2ケース）

## 最初に見るもの
書かれていることが正確かの事実確認。

インシデントなら、まず不具合の程度を位置づける。
- 普通に品質保証活動をしていれば見つけられて当然の、程度の低い不具合なら、「なぜこんな低い水準の不具合が起きて報告に上がってきたのか」「ステージングなど、リリース前に食い止められるべきチェックの結果はどうだったのか」を問う。検証していないと判明すれば、不具合の報告ではなく責任の問題に転じる。
- 稀な環境依存の事象なら、再現方法・再現条件・発生率・依存環境で、報告されたリスク要因が事実かを確かめる。加えて、事業観点でどれほどのリスクかを判断する。そこから以降の報告内容を読む。

## 原因と対策
- 原因がヒューマンエラーであること自体は避けられないことがある。それは現時点のワークプロセスが原因。問題は対策。
- 「ダブルチェックの徹底」は通る理由がない。責任転嫁が生じた際に意味がなくなる。
- 人に依存する問題なら、真の再発防止は人が介在しないシステムが最良。必須かはケースによる。手順が徹底されたら再発しなくなるとは誰も保証できない。システム化する余地が現時点でないと分からなければ差し戻す。
- 対策の承認と実行計画は別。再発防止策は実行されなければ意味がない。「いつから取り組むのか」を聞く。責任者・開始日が無ければ、指摘してその場で答えさせる。

## 報告が上がる経路
ディレクターは現場監督者。この水準の報告が上がる前に、現場に是正・改善指示を先回りして出しているべき。報告は「現場の不手際で、起きてはいけない水準の問題が起きた」と前置きして始まるべきもの。

## 評価
文章全体の在り方で下す。一箇所を切り出さない。対策がヒューマンエラーを確実に除去できるものなら、外に出すことを許可する可能性はある。
