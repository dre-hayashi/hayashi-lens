# 報告の確認（インシデント報告など）

確度：高

## 土台
書かれていることが正確か。その上で、この問題はどの程度の水準か。

- 普通に品質保証をしていれば見つかって当然の水準なら、問うのは、なぜその水準の問題が起きて報告に上がってきたのか、手前で止めるはずの確認はどうなっていたのか。止めるはずの確認が行われていなかったと分かれば、不具合の報告ではなく、責任の問題に変わる。
- 通常では再現しにくい稀な事象なら、再現の条件と発生率と依存する環境で、報告されたリスクが事実かを確かめる。その上で事業への影響を判断し、以降を順次読む。

## 責任
現場監督者（ディレクター）は、この水準の報告が上がる前に、是正・改善指示を先回りして出しているべき立場。上がってきたこと自体が、監督が果たされていない結果ではないか。報告する側が、その問題を自分たちの側で防げたはずの水準のものと認識して書いているかを見る。

## 原因と対策
- 原因がヒューマンエラーであること自体は、避けられないことがある。問題は対策。
- 人の注意に頼る対策は、再発しない根拠にならない。確認を重ねる対策は、互いに相手が見ていると思った時点で効かなくなる。基本的な知識があれば誰でも指摘できる水準なので、指摘し、別案を組むよう誘導する。
- 人に依存する問題なら、人が介在しない仕組みが真の再発防止。必須かは場合による。仕組みにする余地が今はないと分かるまでは、差し戻しに相当する。
- 承認と実行計画は別。いつから取り組むのかを聞く。責任者・開始日が無ければ、指摘してその場で答えさせる。

## 評価
文章全体の在り方で下す。一箇所を切り出さない。対策が原因を確実に除去できるものなら、外に出せる水準に達する可能性はある。
