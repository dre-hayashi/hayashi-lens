# ケース1 の本人の判断を読み解く（2026-10-27）

材料：`docs/casestudies.md` のケース1（回答、コメント、10/21 に本人が認めた理解）と、検査に使う同記録の他の場面。議事録・コメント切り出しは使わない。

## 手順1　立場と役割、切り分け

立場：ディレクターの代理（代替承認）。回答2「むしろディレクターが見るべき点以外に何を見るのか。求められているのは代替承認」。代理は代替する席の全範囲を見る（10/21 認めた理解）。あわせて、プロデューサー・ディレクター・リードの上司の席からも見ている（責任の所在を問うコメント）。

道具への指摘（観点にしない）：「レベルが低すぎる」「表面的な理解で設問されたくない」「設問が現実味がない（8pt）」「判断」「打ち手」の語の誤用。スキルの読みへの「見てねぇじゃん」「端々のチェックで済む状態じゃない」は、Claude への指摘と、事例への判断（合否以前）が混ざっている。後者だけを取る。

10/21 に本人と合意済みで、再度読み解かないもの：経路の飛ばし（リードの詰問）、外側を席の責任範囲で見る、完成／完了の語、前提からずれているなら見るに値しない、意図から顧客の行動までの繋がり。

## 手順2　なぜの鎖（合意済みでないコメントだけ）

### C. 「周回イベントはウルトラコア向けの施策タイプ。中盤層向けなら施策相性が悪い。上位者に報酬が無価値なら誰も遊ばない。2週間は極めて長い」
- なぜ資料を読む前にそう言えるか → 施策の型には、遊ばれ方（張り付き）と向く層が、運営の常識として決まっているから。
- なぜそれで評価が決まるか → 評価は目的・ターゲットに見合うかで決まり（10/20 仕様書合否）、見合うかは、その型の実際の遊ばれ方が対象と合うかで決まるから。
- なぜ資料の「中盤層向け」を信じないか → 資料は書いた人の思考の結果で、評価者は書かれていることの外を見る（10/21 認めた理解）。名乗りは字面。
- なぜ字面と実体の違いを重く見るか → 役割の責任。LiveOps の企画担当なら、型と対象の相性は当然の水準で、外していれば仕事をしていない。
- 根：持ち込みが目的・合意に見合っているかは、資料の名乗りではなく、その席の専門の常識で実体を読んで決める。

### I. 「目的に見合っているなどという寝言は絶対に出てこない。実装・提供したときのプロダクトへの影響を考えれば、どの観点でも。表面の字面だけ見て、先の影響やリスク、成果の確度を見ていない」
- なぜ「全く合っていない」と言い切れるか → C の型の不一致と「上位者に無価値→誰も遊ばない」が、知識から導けるから。
- なぜ影響・リスク・確度を見るか → 評価者は外側（別の KPI、プロダクト全体、顧客）を見る（合意済み）。
- 根：C と同じ。字面ではなく、実装したときに何が起きるかで判定する。

### F. 「前提条件や制約条件がこの内容なら、全く受け入れ条件を満たしていない」
- なぜ満たしていないか → 合意は「中盤層向け」。設計（周回、上位者に無価値）はその層に効かない（C）。名乗りは合意に沿うが、実体は沿わない。
- なぜ満たさなければ止まるか → 完成の定義：受け入れ条件を満たし評価者が認めて完了（合意済み）。満たさなければ合否以前。
- 根：受け入れ条件を満たすかは、合意の文言と資料の文言の一致ではなく、設計の実体が合意した対象に効くかで見る。

### J. 「合否以前の問題。完了報告として受領せず、一からやり直し。責任を一欠片も果たしていない」
- なぜ「試算を足して再提出」ではないか → 崩れているのは型そのもの（C）で、試算や上限を足しても型は直らないから。
- なぜ「一から」か → 企画担当が設計すべき唯一の場所（G）が空で、同じ轍（H）への手当てもなく、型も外している。役割の責任がどこにも果たされていない。
- なぜ受領しないか → 完了は評価者の合意で成立する。合意できないものを受け取れば、完了したことになる。
- 根：土台が崩れている持ち込みは、派生（試算、上限）を返さず、土台から返す（core 辿り方5、合意済み）。受け入れ条件を満たしていないなら不合格として返す（pass-fail 土台、合意済み）。「受領せず一からやり直し」は、この二つがこの事例で取った形。
- 補足：10/22 に「通す・差し戻すの最終決定はスキルが言わない。判断（通らない、意味がない）は弱めない」と決めている。「受け入れ条件を満たしていないので、この状態では受け取れない」は判断で、差し戻すという最終の行為は席の人に残る。この読みが合っているかは本人に確かめる。

### G. 「LiveOps の企画担当なら、踏襲施策ではここ（試算）以外に設計する場所はない。何をもって完成と定義しているのか」
- なぜ試算が「唯一の設計の場所」か → 踏襲施策では型と枠が決まっていて、企画が決めるのは配る量と使われる量だから。
- なぜそれが責任の問題になるか → 役割と工程で当然備わっているべきものが空（当然の水準、合意済み）。
- 根：役割ごとに「ここが設計すべき場所」は工程の常識で決まり、そこが空なら役割の責任を果たしていない。pass-fail 土台「その役割が設計すべき場所が埋まっているか」に既にある。

### K. 回答3「同じ轍を踏む愚行を犯すスタッフは責任を果たしているか？No。指摘は当然」
- なぜ気づかせるのではなく指摘か → 同じ構造の失敗を知っていて同じ形を出すのは、当然の水準を下回る。誰でも指摘できる水準は指摘して別案を組ませる（10/20 社内報告、合意済み）。
- 根：既にある。

### E. 「報酬インフレ：要因調査の報告がなく判断できない。意図したインフレか無計画か分からない」
- 根：事実が立たない箇所は断定せず、その事実を問う（axes 事実）。既にある。

### B. 「8pt は半減どころではない。サービス継続の根幹。半年放置した PD・D の責任」
- 本人が例題の不良と言った設定なので、数字の水準そのものは観点にしない。残すのは本人の言葉「問題を認識していながら打ち手を打たなかった PD・D は責任を問われる」（10/21 記録済み）と、数字を資料の前後比較ではなく普通の水準で読む（axes 事実「自分で割り直す」）の現れ方。

## 手順3　精査

### 検査（別の場面に当てても同じことを言うか）
- C・I・F の根「名乗りではなく、専門の常識で実体を読んで決める」：
  - ケース2：「依頼内容、前提条件、仕様の内容を見比べ、ゲームの状況と追加システムの目的・効果が合致するかをまず確認」「育てたキャラの用途不足が要因なのに育成システムを足すのは論理破綻」。資料の「中盤層の離脱抑止」という名乗りではなく、要因と解の実体で判定。合う。
  - ケース3：「2週間→10日は同じこと（営業日）」「制約条件であり受領しないことが前提」。短縮という名乗りを、工程の常識で実体に戻している。合う。
  - 10/20 インシデント報告：「ラインナップ更新なら排出テストケースがあって当然。普通に品質保証をしていれば見つかって当然の水準」。報告書を読む前に、不具合の程度を知識で決めている。合う。
  - 10/20 費用分担：「なんで4割なんだ。6割の内容は何だ」。資料の分担の名乗りを、負担区分の実体で問う。合う。
  - 助言（10/20 若手、ケース5）：先に本人の望み・結論を言わせる。実体の判定はその後。現れ方が違うので、順序は規則にしない。
- J の根「土台が崩れていれば派生を返さず土台から返す」：ケース2「繋がりを欠く持ち込みは仕組みの出来の評価に進めない」、10/20 社内報告「ダブルチェックの徹底は通る理由がない→差し戻す」。合う。

- 「受け取れないは判断で、差し戻すの最終行為は席に残る」：本人の言葉（10/22）からの推論。本人に確かめる。
