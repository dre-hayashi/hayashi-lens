# タスク

本人が「タスクに追加して」と言ったものを、本人の言葉と一緒に置く。スキルを変えるものは、決められた手順（立場と役割の確認、なぜを繰り返す、別の相談に当てて確かめる、設計を本人に示す）を経てから着手する。

## 1. スキルの利用開始時に、相手が何者かを聞き、各環境に記録する動きを作る（2026-11-21）

- 本人の言葉：「スキルの返答ターゲットが定まらないということか？相手が何者かを特定して限定する動きが必要そうか。薄々感じていたが、スキルを動かすたびに相手が何者か？を問うていたらあかんわな。スキル利用開始時に相手のことを聞いて、それを各環境に記録する動きでも作るか。タスクに追加して。」
- 元になった課題：スキルの返事の相手が定まらない。検証前のスキルにそのまま通した9件のうち4件で、スタッフが部長に宛てた相談に、部長に向けた「返信案」を出した。スキルの一つ目の手順（受け取る）が作業メモに書くのは、本人が求めていること、誰に届くか、どの立場で判断するか、の三つで、誰に返すか・相手が誰かを決める所が無い。
- 本人の言葉（同日、続き）：「返す相手は決まってるだろ。なんで聞いてきた相手への返事やFBじゃなくて別に向くんだ。対話相手以外に目線行くのおかしいよね。だから初期設定フェーズで相手の記録すれば以降問題にならんやろ。」
- 分かったこと：返す相手は、スキルに話しかけてきた相手。スキルに判断させるものではなく、前提。部長本人が使うときは、話しかけてきた相手が部長なので、同じ前提で足りる。
- テストの側の原因：検証前のスキルに通した九件の入力は、どれも「【Slack　役割 → 部長】」という見出しの付いた貼り付けの形で、誰がスキルに話しかけているのかが入力から読めなかった。同じ形で、4件は部長に、5件は本人に返した。
- 状態：未着手。スキルの更新には手を入れない（本人の指示）。

## 2. 「進めてよい」と言う基準（合格基準）の設計を作る（2026-11-21）

- 本人の言葉：「私の考え方を反映する手順は作ったけど、合格基準に関する設計が抜けてるということ？？あら探しのためのスキルじゃないと何度も伝えたけど、打ち手は今まで何もしていないということかな？もしそうならタスクに追加して」
- 事実：打ち手は入れてある（`docs/skill_provenance.md` の 11/10〜11/11。全体として進められるかを先に答える、進めてよいなら進めてよいと返す、根拠をどの相談にも求める箇所を外す、仕事の定義を「評価して返す」から書き直す）。考え方の文書（`references/core.md`）にも「任せる相手に、自分と同等は求められない。求める水準は、役割と場面から引く」がある。それでも、検証前のスキルは、直す所の無い相談4件すべてで求めを二つ以上出した。
- 抜けている所：「進めてよい」を決める四つ目の手順が、役割から引いた水準ではなく、スキル自身が三つ目の手順で書き出した「結果に届くまでに要る手」が全部あるかで判定している。考え方にある水準を、判定する手順が使っていない。
- 状態：未着手。スキルの更新には手を入れない（本人の指示）。
