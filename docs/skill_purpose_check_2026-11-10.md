# スキルは「ダメ出しのための道具ではない」と理解して作られているか（2026-11-10）

本人の言葉（11/10）：「そもそも論として、このスキルはダメ出しをするためのスキルじゃないんだけど、そこを理解して構築されているのかをまずちゃんとみてよ」

スキル本体（11/02 の状態、de5a0d5）の全ファイルを読み直して確かめた。直しはしていない。

## 訂正（11/10）

この文書は、スキルの文面だけを読んで「果たしている所が返事に入らない」と断定した。実行の記録と照合していなかった。ケース10 一回目の返事は、噛み合っている所を認める言葉を書いている。下の表の「筋が通っていても、同意を書けない」は事実と違う。本人の考え（10/22）から見直したものは `docs/design_purpose_2026-11-10.md`。

## 答え

理解して作られていない。「指摘を並べるな」という注意は書いてあるが、何のための道具かが手順の出発点に無い。手順がやらせているのは、足りない所を見つけ、絞って、返すこと。つまり「ダメ出しを上手にやる道具」として作られている。

## 目的がどこに書いてあるか

- スキルの冒頭の説明は「資料・報告・相談・企画書を評価しFBを返す」。
- 10/20 に本人が認めた理解は「スキルは資料の体裁を整えるためではなく、書いた人が役割を果たした状態で持ってこられるようにするため。指摘の列挙は手段」（casestudies.md）。このうち「指摘の列挙は手段であって、目的ではない」だけが core.md に入っている。「書いた人が役割を果たした状態で持ってこられるようにする」は、スキルのどのファイルにも無い。
- 10/27 に整理した目的（本人が理解し、納得して、次の持ち込みを変える）は、SKILL.md の手順6 に一文あるだけ。手順6 は返事を書く所で、返事の中身は手順4 までで決まっている。
- core.md「人に対して」には「指摘を並べるのではなく、本人が自分で答えられる状態にする」「直すべきは資料ではなく本人の役割の責任の果たし方」がある。どちらも、直す所がある相手への向き合い方として書かれている。

## 手順がやらせていること

| 場所 | 書いてあること | 役割の責任を果たしている相手のとき |
|---|---|---|
| checks.md（読むときの確認項目、13 種類） | 当てて、引っかかった所を作業メモに書き出す | 書き出すものが無い |
| SKILL.md 手順4 | 論点を二択にして答える。「果たしている／いない」 | 「果たしている」と答えても、その答えの行き先が書かれていない |
| SKILL.md 手順5（どう返すかを選ぶ） | 選ぶ材料は五つ。当然の水準を下回る、方向性が定まっていない、繋がりが切れている、合意からずれている、材料が足りない | 選ぶ材料が無い |
| feedback.md（返事に載せるもの） | 六種類。五つは足りない所、一つは本人に答えさせること | 「指摘なし」と書けるだけ |
| style.md（返事の書き方） | 「受け止めるのはそこまでで、本人の理屈には同意しない」。最後は「次に何を整理してほしいか」 | 筋が通っていても、同意を書けない。整理してほしいものが無くても、その形で終える |
| audit.md（出す前の検査） | 返事を「指摘と問い」の集まりとして、一つずつ要るかを検査する。置いた理由も「部長は、指摘と懸念の重要度で取捨選択」 | 検査の対象が無い |

## 場面ごと

| 場面 | 相手を前に進ませることが目的として書いてあるか | 満たしているときの返し方 |
|---|---|---|
| advice（助言） | ある（本人が自分で進む方向を見定められる状態になる） | ある |
| consult（相談） | ある（本人が一人で決められる状態にする） | 一部ある（最良を追った結果の妥協は認める） |
| report（報告） | 無い | 無い |
| external（外に出すもの、交渉） | 無い | 無い。交渉の項は「最初から及第点に置いた案なら再考を求める」だけで、ベストを目指した案のときが書かれていない |
| approval（承認） | 無い | 無い |
| plan-deviation（計画から外れる提案） | 無い | 「認める線：内容とタイミングで決める」の二行 |
| pass-fail（合否） | 無い | 無い。「満たしていなければ不合格として返す」だけ |

満たしているときの返し方が、場面をまたいで書いてあるのは core.md「任せたものは、点数ではなく目線で見る」の「言えればその線で認める」の一か所。

事実として：本人が「このスキル返答は望ましい」と言ったケース9 は、相談の場面。本人が「過剰に責める」と言ったケース10 と、「ところ構わず根拠を求める」と言ったケース8 は、交渉の場面。

## なぜこうなったか

スキルを組むとき、Claude は 10/20 の各場面の「最初に何を見るか」「何を問うか」を手順にした。「それは何のためか」は、注意書き（指摘の列挙は手段）としてだけ入れ、手順の出発点に置かなかった。11/10 の読み解きで「返事を組む所だけが繋がっていない」と書いたのは、狭すぎた。読む所から検査まで、全部が足りない所を扱う作りになっている。

## 直す場所

文言ではなく、目的がスキルの手順の出発点に入っていないこと。各手順が、目的（本人が役割の責任を果たした状態になる）から始めたら何をすることになるかを書き出し、本人に見せてから作る。
