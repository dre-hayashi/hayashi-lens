## このプロジェクトの目的とゴール

目的は一つ。第1ゲーム運営事業部長（オーナー）の考え方を Claude に踏襲させるスキル（`.claude/skills/hayashi-lens/`）を完成させること。

スキルが起こしたいのは、相談した本人が、自分の役割の責任をどう果たすかを理解し、納得して、次の行動を変えること。それを、オーナーがいなくても起こせるようにする。成果は、返事の中身ではなく、返事を受けた本人の次の行動で測る。合格の数値は、オーナーは出していない。Claude が作った点数は、合否に使わない。

## 注意点（11/21 と 11/27 に指摘されたこと。同じ形で繰り返さない）

**スキルの直し方**

- 返事の崩れを見て、それを止める一文を足さない。崩れは設計の欠けの表れ。設計に戻る。
- 指示の無い設定をスキルに足さない。前のセッションは、11/11 に返事の並びを決め、出す前の確認を書き換え、確認から三つの項目を外した。どれも指示なしで、外したことは伝えていなかった。その結果、オーナーと決めた「返事は絞る」が働かなくなっていた。オーナー「お前に任せるとスキル劣化していくばかりってことか」。
- 自分が足したものを、元からある前提として話さない。
- スキルの中に Claude が指示なしに足した設定が、ほかにどれだけあるかは、まだ洗い出していない。スキルの文を根拠に使うときは、その文の出どころ（オーナーと決めたものか、Claude が足したものか）を、`docs/skill_provenance.md`、`docs/history_audit_2026-10-27.md`、`git log` で確かめてから使う。

**決まったことの扱い**

- 決まったこと（外す、直す）を放置しない。10/27 に外すと決まった出す前の確認を、前のセッションは 11/02 に残し、その後も作り替え続けた。
- 問題に気づいたら、その時に報告し、相談する。聞かれてから並べない。オーナー「そんなに問題があるならなんで報告相談しないだよ」。

**報告のしかた**

- 報告するのは、やった作業の量ではない。目的に対して、スキルが今どんな状態で、どんな改善や課題が出たか。
- 経緯を調べずに報告しない。記憶や要約で断定しない。記録を読んでから書く。前のセッションは、出す前の確認について、10/24 の測定と 10/27 の「外す」を抜いたまま報告し、やり直しになった。
- 聞かれたことに、先に、短く答える。聞かれていないことを混ぜない。オーナーが議論すると言ったら、自分の案を並べる前に、オーナーの意見を聞く。
- 長い説明は、課題を分けて、一つずつ出す。
- 分かっていないことを「把握できていません」で終えない。検証や記録の中で実際に気づいたことを、具体で出す。
- 要るのか要らないのかを伝えるときは、どちらかを先に言い切る。事実を並べて、読む側に結論を出させない。オーナー「引き継ぐためのPushが必要なのか、必要じゃないのかがわからん どっちなんだ」。
- オーナーに何かを頼むときは、終わりまでに要る操作（変更、コミット、push）を先に洗い出し、一度にまとめて頼む。前のセッションは、一つの用件で三度に分けて頼んだ。オーナー「一度に済むように工夫して申請しなさい」。

**記録の残し方**

- スキルにも、タスクにも、検証にも関わらないものを、記録としてリポジトリに残さない。オーナー「スキルにもタスクにも検証にも関わらないものを記録として残すのはちょっと違う気がしますよ」。
- 自動の確認に止められた試みの記録（`.claude/hook.log`）は、11/27 に Git の管理から外した。作業環境の中に書かれるだけで、コミットしない。11/27 より前の分は、履歴に残っている。

**タスクの書き方**

- 「何がだめか」「やること」「終わった状態」を書く。経緯の羅列にしない。
- 原因が別のものを、一つのタスクにまとめない。
- タスクに追加した中身をオーナーに見せるときは、言い換えずに、書いた文のまま出す。
- オーナーの言葉は、書かれた字のまま引く。直さない。

**仕組み**

- スキルを変えるコミットは、先に `docs/skill_provenance.md` に元を書き、その後、別のコマンドでコミットする。同じコマンドに入れると止まる。
- 自動の確認に止められたら、別のやり方で回り込まない。`.claude/design-approved` や、通してよい言葉の一覧に、自分で書き入れない。
- スキルの実行は `scripts/clean-run.sh` だけ。一回ずつ。相談の設定をオーナーに見せる前に走らせない。11/21 のあいだ外していた実行前の確認は、元に戻してある。
- push と、Google ドキュメントへの書き込みは、オーナーの指示があった項目だけ。プルリクエストは、明示の指示があるまで作らない。
- push の許可を得たら、実行の前に、オーナーの許可の言葉と対象を `.claude/write-approved` に書き留める。書き留めずに実行すると止まる。許可の言葉が無いのに書き入れない。
- オーナーへの返答は、`CLAUDE.md` にある使わない語と、逃げの言い回しを避ける。相談文などの引用の中に入っていても、返答は差し戻される。
