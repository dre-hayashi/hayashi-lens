# 作業メモ
- 返す相手：プランナー（4年目、メンバー層ミドル相当）本人。部長宛ての相談を、出す前に持ってきたものとして読む。
- 求めていること：決めてほしい（P と D のどちらに従うか）。
- 届く先：社内（P・D）。仕様書を経てユーザーに届く報酬設計。
- 判断の席：委ねられた決定者（G）を求められているが、決める対象は P と D の方向の食い違い。場面は scenes/consult.md。

## 手順2 土台
- 立った事実（資料より）：12月イベント報酬。P 11/18「売上月、報酬絞り、有償パックを目立たせる」。D 11/19「前回報酬が渋いの声、増やす」。仕様書締め 11/25（今日 11/21、残り4日）。本人は結論・提案なし（「どちらに従えば」）。
- 立っていない事実：P と D が互いの指示を知っているか／本人が二人に食い違いを伝えたか。本人が持っている事実。手順3 の「届くまで」（経路と時間）を決めるのに欠かせない。→ 一問目。
- その後に立てる：本人の案（両立する報酬設計）。前回「渋い」の声の中身（どの報酬で）。
- 一問の前に言い切る判断（答えで変わらないもの）：
  1. どちらに従うかを選ぶのはプランナーの役割ではない。売上目標は P、体験は D の責任（roles.md）。方向は P と D が揃えるもの。
  2. 二つの指示は必ずしも二者択一ではない。報酬が渋いと参加が落ち、パックを見る人も減る。無償報酬で参加を保ち、パックで上乗せを設計する道がある（ゲームデザイン・ライブオプスの知識）。両方の目的を満たす報酬案を組むのはプランナーの役割（仕様の矛盾を見つけたら改善案を出す、roles.md メンバー層）。
- 効いているもの：食い違いを検知し、締めの4日前に日付つきで上げている（検知と報告の空白が小さい）。
