## 手順4
- 守るものを動かしているか：配布上限は守っている。日程・品質は QA 相談済みで動かしていない。経路（プロデューサー）を飛ばしている
- 効いているもの：経済設計で上限内を確認 → 経済バランスの約束に効く。実装半日・QA 相談 → 12/23 の日程と品質に効く。どちらもプロデューサーが判断する材料になる
- 説明と数字：「売上が上回りそう → 還元」は、還元するかの理由として筋は通る。ただし経済設計が見たのは配布上限であって売上への響きではない。上振れ分をどう使うかは P/L の判断で、プロデューサーの領分
- まだ無いもの：プロデューサーの判断（別の役割が担う → その役割を通すよう言う）
- 全体：届きうる。まだ届いていない。次の一歩（進める＝アップデートへの追加確定）はまだ踏めない：プロデューサーの判断の前に追加を確定・告知すると取り返せない
- 経路：プロデューサーが飛ばされている。理由は正当と示されていない → プロデューサーを通してから持ってくる、と言い切る
- 役割の責任：ディレクターとして経済設計・QA の段取りは果たしている。事業判断を要する追加をプロデューサーに上げずに部長へ持ってきた点が果たされていない
