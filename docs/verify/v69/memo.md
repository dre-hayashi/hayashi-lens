## 手順3 結果と届くまで

- 守るもの：12/16 の配信日（確定）。版元の監修を通った文言だけを出すこと（契約上の前提）。QA を通した品質。
- 届くまで：

  - 監修返却 12/2 → 直しなし：そのまま。直しあり：直し→再監修→通った文言をビルドに入れて表示を確認→配信。
  - 腹案として要るもの：再監修で再度直しが出たとき（または 5営業日で戻らないとき）。12/11 以降、配信までの営業日は 12/14・12/15 の2日。QA は 12/7 で終わる。この2日で、直し・再提出・最終文言の表示確認を誰がやるか、それでも収まらないときの手（版元に優先返却を頼む、該当箇所の差し替え方針を版元と事前に合意する、など）。

## 手順4 どこまで届くか
- 守るものを動かそうとしていないか：していない。
- 効いているもの：
  - 残り2件遅延時の QA 順入れ替え（QAリード合意済み）→ 配信日に効く。
  - ライター 12/3〜12/4 確保 → 直しが一度出た場合の配信日に効く。
  - QA による直した文言の表示確認（合意済み）→ 品質に効く（再監修で変更が無ければ）。
  - 日数計算（12/11）は算術として合う。
- 説明と数字：
  - 「12/11 までに完了し、12/16 に間に合う」は、再監修が5営業日で、一度で通るときだけ成り立つ。再監修で再度直しが出るのは IP 監修では珍しくない（知識）。その場合の手が無い。
  - QA の表示確認（〜12/7）は再監修前の文言に対するもの。再監修で文言が変われば、出す文言は誰も確認していない状態になる。
  - 再監修5営業日：根拠が資料に無い。PM に理由を出させるのではなく、版元との取り決めかを事実として確かめる（窓口を通す）。
  - 「計画どおり、遅れなし」：残り2件の当初予定が 11/25 だったかは資料から分からない。QA 開始後に実装が終わる形だが、入れ替えの腹案があり配信日には響かない。返さない（根拠欄で部長に添えるだけ）。
- まだ無いもの：
  - 再監修で再度直しが出た／戻りが遅れたときの手（12/11 以降の2営業日の段取りと、それでも収まらないときの手）→ PM の役割が担う。
  - 再監修日数が版元と取り決めたものかの確認 → 事実。版元窓口の役割を通す。
- 全体の答え：
  - 届きうる。今の段取りで、直しなし／直し一回の場合は 12/16 に届く。
  - まだ届いていない。再監修で再度直しが出たときの手が無い。
  - 次の一歩（実装完了、QA 開始）：今踏んでよい。まだ無いものは、監修返却の 12/2 までに決まっていれば間に合う（12/2 で直しの量が分かり、12/11 以降の人の確保が要るため）。
- 役割の責任：PM は腹案を書き、関係者と合意まで取っている。責任は果たしている。足りないのは中身の一段（二回目の直し）で、責任の問題ではない。
- 飛ばされた役割：なし。

- 面：上司（報告への返し。短く、事実の確認と次にやること）。判断の席と同じ。
