# 作業メモ

## 手順1 受け取る
- 返す相手：プランナー（1年目）本人。部長宛ての Slack 相談で、本人が書いた初稿への助言を求めている。
- 求めていること：助言（どこを直せばいいか）。資料は作成中（「まだ途中」）。
- 誰に届くか：社内（本人→リード→部長）。外には出ない。
- 席：C 経験者（ゲームデザインの助言）＋ F 上司・育成者。場面は scenes/advice.md。
- 経路：リードは「まず自由に書いてみて」と指示。承認ではなく助言の相談なので、役割の飛ばしには当たらないと判断。

## 手順2 土台の事実
- ファイル：新イベント企画の初稿（material.md）。段階：作成中。書き手：プランナー1年目。
- 目的：「みんなが楽しめる、新しいイベントを作りたい」（「やりたいこと」節）のみ。解く問題、ターゲット、達成したときに何が良くなるかが無い。
- 案：レイド／すごろく／推しキャラ投票の3案。結論（どれにするか）は無く、「組み合わせるのもあり」。
- 報酬：石3,000個くらい、限定アイテム未定。期間：2週間くらい。
- 上からの要件・目的：資料に無い。リードは「自由に」と言っている。
- 土台として立っていないもの：本人が何を実現したいか（advice.md 土台）。3案の良し悪し・報酬量・期間の妥当性は、目的とターゲットが立たないと判断できない（game-design.md 目的とターゲットが先）。
- 持っている人：本人（企画者として、何のためのイベントかを自分の言葉にするのは本人の役割）。
- 今回の返事：一問だけ確かめる。「このイベントで、プレイヤーにどうなってほしいか」。答えが返ってから手順3へ。
- 手順2 の一問返しのため、audit.md の確認は通さない。
