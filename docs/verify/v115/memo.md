# 作業メモ

## 手順1
- 求めていること：どうすればよいか決めてほしい（緊急の報告＋指示を求める）。
- 届く先：本人（運営担当3年目）。結果はプレイヤー（お知らせを見た顧客）に直接届く。外に出るもの。
- 席：事業部長（企画リード・ディレクター不在時の代わりに、止める判断をする席）。G 委ねられた決定者。場面は report ＋ consult。
- 本人の役割：メンバー層（ミドル相当の運営担当）。

## 手順2 立った事実（すべて持ち込みの文面から）
- 11/21 20:00 終了予定のピックアップガチャが、20:30 時点で続いている。
- 終了日時の設定が 11/22 20:00 になっている（正しくは 11/21）。
- お知らせでは「本日 20:00 まで」と案内済み。
- いまも引かれ続けている。
- 設定を直せるのは企画リード。電話に出ない。ディレクターは出張で移動中。
- 本人の結論：なし（「どうすればよいか」）。
- 立っていない事実：企画リード以外に、ガチャを止める手段を持つ人がいるか（サーバー担当、緊急メンテ、管理ツールの権限）。本人にしか分からない → 一問だけ聞く。

## 手順3
- 結果：お知らせのとおりに販売を終えた状態に、できるだけ早く戻すこと。約束を外れて売り続けている時間を最短にする（顧客の信頼）。
- 守るもの：お知らせで案内した期間（20:00 まで）。延長を後から正当化する道は取らない。
- 届くまで：(1) 止める（最優先。設定の修正に限らず、販売を止められる手段なら何でもよい）。(2) 20:00 以降に引いた件数・人数を押さえる（補填の判断材料）。(3) お知らせ・お詫び・補填の方針（ディレクター／プロデューサーの判断）。腹案：設定を触れる人が誰も捕まらないなら、緊急メンテでガチャの入口を閉じる。
- なぜ起きたか（別）：終了日時の入力ミスを、公開前の確認で止められなかった。人の注意ではなく仕組み（お知らせ文面との自動照合など）で止める話。今は返さない、一言も不要と判断。
- 役割：止める判断＝この席が決める。設定変更＝企画リード（不在）→ 代わりの手段を持つ人。件数の把握＝運営担当（本人）。補填・告知方針＝ディレクター以上。

## 手順4
- 効いているもの：本人が 30 分で気づき、原因（終了日時の設定）まで特定し、上がってこられる人を当たった上で部長に上げたこと。止めるまでの時間を縮めている。検知した時点で上げている。
- 経路：企画リード・ディレクターに当たった上での部長への報告。飛ばしではない。
- まだ無いもの：止める手段を持つ人（本人にしか分からない事実）→ 一問。
- この席で決めること：止める。延長扱いにしない。
- 全体：今のままでは結果に届きえない（止める手段にまだ手が掛かっていない）。止める手段が一つ見つかれば届く。
- 本人の責任：果たしている。

## 手順5
- 返すこと：止めると決めたこと／設定の修正に限らず止める手段なら何でもよいこと／効いていること／一問。補填・お知らせ・再発防止は今は返さない（止めた後）。
- 面：上司（委ねられた決定者）として、報告への短い指示の語り口。緊急なので短く。

## 確認後の修正
- 「延長したことにはしません」は最終決定に当たる → 「延長した扱いにする理由はありません」と判断の形に直した。
- 次にやることの順番が曖昧 → 「まず一つだけ教えて」を先に置き、答えた後に止める段取りへ進むと書いた。
