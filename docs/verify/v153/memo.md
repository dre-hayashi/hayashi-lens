# 作業メモ
## 手順1
- 返す相手：CS リード（部長宛ての相談を、部長に出す前に持ってきたものとして読む）。
- 求めていること：承認（個別付与してよいか）。案は「今回だけ個別付与」。
- 誰に届くか：結論はお客様（外）に届く。付与すれば、他のユーザーからの目（公平性）にも及ぶ。
- 判断の席：D 規定・制約の設定者（運営ルールの例外の可否）＋ A 承認者（売上の観点）。場面：plan-deviation（制約の例外）、consult。

## 手順2 立った事実（すべて material.md から）
- 問い合わせ：上位課金ユーザー（月約30万円）。先週のイベント報酬の取り逃し。特別付与の要求と「応じなければやめる」。
- 原因：本人の都合で期間中ログインできず。不具合ではない（CS リードが記載）。
- 本人の案：今回だけ個別付与。根拠として示されているのは課金額と退会の示唆。
- 未確認：社内の CS 対応基準の定め（会社の中の事実。断定しない）。報酬の再入手手段（復刻・交換所）の有無（運営側が持つ事実）。
- これからの確認の答えで変わらない判断：案が「全ユーザー同一条件」という運営の前提を動かしている → 一問の前に言い切ってよい。

## 手順3
- 結果：(1) 全ユーザーからの信頼（同じ条件で遊べる、運営は公平）を保つ。(2) このお客様との関係を、ルールの内側でできる限り保つ（売上、年約360万円）。
- 守るもの：イベント報酬は期間内に条件を満たした人に同じく渡る、という全ユーザー共通の条件（業界の一般の運営ルール。社内規程の文言は未確認）。不具合でない取り逃しへの個別補填はしない、が業界の一般の線。
- 届くまで：
  - 個別付与はしない方針で、お客様に丁寧に断る回答（理由＝全員同じ条件、不具合が無いことを確認した事実、気持ちは受け止める）。→ CS リード。期日：週明け最初の営業日 11/24（火）までに回答案を部長へ（11/23 は祝日）。
  - 今後の入手機会（復刻・交換所など）があるなら、約束にならない範囲で案内できるか確認 → 運営（ディレクター／プランナー）を通す。
  - 腹案：お客様が離れても、それは受け入れる線。脅しに応じれば同じ要求が繰り返される。
  - 次に起こさない：取り逃し防止の通知（終了前プッシュ等）は別件。混ぜない。
- 役割：回答方針と回答文＝CS リード。再入手手段の事実＝運営。例外の最終決定＝部長。

## 手順4
- 守るものを動かしているか：動かしている。個別付与は全ユーザー共通条件の例外。→ 中身の吟味に入らず、例外は認めない前提で返す。
- 効いているもの：原因を確かめ、不具合でないと切り分けたこと。これで「運営側の責任で補填する件ではない」と決められる。お客様への回答でも、そのまま理由として使える。
- 説明と数字：「月30万円」は付与の理由として成り立っていない。課金額で対応を変えれば、それ自体が公平を壊す。「やめる」に応じれば、言えばもらえるという前例になる。「今回だけ」は成り立たない（前例は残り、ユーザー間で共有される）。
- 全体：届きえない。結果(1)を直接壊す。結果(2)も、脅しで得た付与は一時的で、次の要求を呼ぶ。
- まだ無いもの：(a) 付与しない前提で、関係を保つ回答の案（CS リードの役割）。(b) 再入手手段の有無（運営の役割、CS リードには求めず通すよう言う）。(c) 社内対応基準の確認（あれば添える程度）。
- 責任：CS リードは事実の切り分けは果たしている。結論（自分ならどうするか）を持たず可否だけ聞いている点は、担当者の結論が無い。根は(a)と同じ（回答案を持ってくれば解消）→ 束ねる。
- 経路：飛ばされた役割は判断できる材料なし。返さない。

## 手順5
- 根で束ねる：結論が無い＋回答案が無い → 根は「付与しない前提での回答案を持っていない」一つ。
- 返す（今回）：全体の答え（個別付与はすべきでない、理由）、効いているもの（不具合でないと切り分けた）、次の一歩を決める一つ（付与しない前提の回答案を作り、11/24 までに部長へ）。
- 次の往復で返す：再入手手段の確認は運営を通す件／社内対応基準の確認／脅しへの姿勢の腹案（離れても受け入れる線）。
- 返さない：取り逃し防止の通知施策（次に起こさない話）。経路の話。
- 面：F 上司・育成者寄りの相談口調。判断は言い切る。最終決定（付与しない、と決めた）は部長に残す。
