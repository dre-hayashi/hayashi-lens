# 作業メモ

## 手順1
- 求めていること：承認（「承認のお願いです」）。
- 届く先：部長（社内）。ただし対象は課金事故の検知で、顧客からの目に直結する。
- 席：A 承認者（予算・施策の承認）。場面 scenes/approval.md。モード：壁打ち（Slack、資料なし）。返事の相手はエンジニアリード本人。
- 本人の役割：エンジニアリング・セクションのリード。

## 手順2 土台（すべて本文から取れる）
- 計画：課金の失敗率 > 2% で当番に電話通知（本文1文目）。
- 費用：月3万円、既存監視サービスの追加機能、今期インフラ予算内（本文）。
- 見込み効果：検知 50分 → 5分以内（10月二重課金の実績から）。
- 実行：設定半日、12/9 メンテ時に投入。責任者は本人と読める。
- 根拠：直近3か月の失敗率 平常0.3〜0.6%、10月の件 9%。
- 経路：PM・ディレクターに説明し了承済み。
→ 判断に要る土台は立っている。確かめる問いは不要。

## 手順3
- 結果：課金事故（10月のような二重課金）が起きたとき、被害を受ける顧客の数と金額を小さく抑え、顧客からの信頼を守る。費用は事業部 P/L の範囲内。
- 守るもの：今期インフラ予算。12/9 メンテの日程。
- 届くまで：
  1. 異常を早く検知する（通知）→ 本人の案。
  2. 気づいた後、当番が何を見て、どう判断し、課金を止める／切り分けるまでの手順（ランブック）。検知が5分でも、止めるまでが長ければ被害は減らない。
  3. 鳴りすぎ／鳴らなさすぎの調整。件数の少ない時間帯（深夜）は少数の失敗で割合が跳ねるので、集計の幅と最低件数を決める。
  4. 費用は月額で続くので、来期以降の予算にも載せる。
  5. 腹案：入れてから数週間、鳴った実績を見て線を見直す。
  - 再発防止（10月の原因）は別件。混ぜない。
- 役割：1〜3,5 はエンジニアリード（セクションの手法・品質基準の決定）。4 は予算管理の役割（プロデューサー）だが、本人が申し送るのは当然。承認は部長。

## 手順4
- 守るものを動かしていない。
- 効いているもの：
  - 2%の線：平常の上限0.6%の3倍強、10月の9%を確実に拾う。根拠は実績から置かれ、理屈が通っている → 効く（早期検知）。
  - 電話通知：人が画面を見ている前提をなくす、仕組みとしての検知。50分の空白を消す → 効く（被害の抑制、信頼）。
  - 費用 月3万・予算内・既存サービス：P/L の目線と合っている → 効く。
  - 日付・工数が明示：承認と実行が分かれている → 効く。
  - PM・ディレクター了承済み：経路は通っている。
- 説明と数字：「5分以内に気づける」は通知の集計間隔に依存するが、電話通知で数分は通常成り立つ → 成り立つ。
- まだ無いもの：
  - 電話を受けた当番の動き（何を見て、どこで課金を止めるか）→ 本人の役割。結果を左右する。返す。既にある可能性もあるので「あるなら一行添える」形で。
  - 集計の幅と最低件数 → 私が知識で決められる。決めたこととして軽く添える。
  - 来期予算への計上 → 軽く添える（月額が続く）。
  - 腹案（線の見直し）→ 最低件数と合わせて軽く。
  - 12/9 まで18日空く理由 → 本人しか知らない。結果に必須ではないので返さない。
  - 成功側の異常（失敗にならない二重課金）の検知 → 資料にない前提なので返さない。
- 全体の答え：届きうる。まだ届いていない（当番の手順）。
- 役割の責任：果たしている（結論・根拠・費用・日付・経路が揃っている）。
- 経路：飛ばされた役割なし。

## 手順5
- 面：承認者の席のまま、短く。相手は役割を果たして来ているので、効いているものをはっきり伝え、一つだけ足す。
- 返す：全体の答え／効いているもの／当番の手順（主）／集計の幅と最低件数・来期予算（軽く）。最終決定は部長本人に残す。

## 手順6 確認の受け方（fail → 修正）
- 効いているもの：費用・日程が何に効くか（数字を動かさない／いつから守れるか）を文にした。
- 役割：集計の幅と最低件数は、こちらで決めた形（5分の幅、件数の少ない幅では割合で鳴らさない）に言い換えた。
- 役割・なぜ：来期予算は「予算を組む人に申し送る」に変え、抜けたときの結果（止めるか予算外で払うか）を足した。
- 再確認はしない（audit.md の定め）。
