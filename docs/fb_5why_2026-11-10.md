# スキルの動作結果への本人の FB を 5Why にかけ、スキルに入れる本質を抜き出す（2026-11-10）

本人の言葉（11/10）：「5whysはスキルをアップデートしたい場合は確実に行われないといけない。スキルの動作結果に対して私のFBがなければそもそもスキル更新の話にならない。私の意見や軸、本質に関わるFBを受け取って、5whysでスキルに落とし込むべき汎用的な本質を抽出し、それをスキルにどう組み込んで改良するかを熟考する」

対象：ケース7・8・10 の返事への判断、11/09 の「良さそう」、11/09 の「一長一短」。10/22 の言葉への 5Why は `docs/casestudies.md` の末尾。
「なぜ」への答えは、本人の立場に立って Claude が推し量ったもの。全部が推察。本人の言葉は、支えとして横に置いた。本人の合っている／合っていないを得るまで、スキルには入れない。

## 1. 5Why

### ケース8（立場：契約と交渉に責任を持つ人）
出発点：8% と 10% の根拠を問う返事に「そんなに突っ込むポイントではない」。
1. なぜ、突っ込むポイントではないのか。→ 落とし所の置き方として外れていない。外れていない数字の根拠を出させても、交渉の結果は変わらない。
2. なぜ、結果は変わらないのか。→ 交渉は相手があって動く。最初に置く数字は出発点。結果を決めるのは、こちらが何を取りたいかと、相手が譲らないときにどう動けるか。
3. なぜ、それが結果を決めるのか。→ 相手も自分の事情で主張してくる。こちらに言い分と別の手がなければ、相手の言い値を飲むしかなくなる。
4. なぜ、飲むしかない状態を避けるのか。→ 払う費用に見合うものを、事業として得る責任がある。飲まされた条件は事業の損になり、次の交渉の前例にもなる。
5. なぜ、その責任から返し方が決まるのか。→ PM の方針を見る目的は、方針の出来を採点することではない。事業として得るべきものを得られる交渉にすること。問うのは、そこに効く点。
支え：「落とし所の初回設定としては悪くない」「（決裂時の手は）良い観点」「我々の事業目線でより望ましい形になるよう交渉をする」「こちらの言い分や考え方をぶつけて協議する」
行き着いた所：問うのは、その件で成し遂げることに対して、結果を左右する点。資料の中で根拠が書かれていない点、ではない。

### ケース7（立場：計画を承認した事業責任者）
出発点：原因を問う返事に「再発防止の話は別口」「本質は届かない領域を埋めるアイディアで、その有無や計画の見通しを問う」。
1. なぜ、原因を別口にするのか。→ 今この場で決めなければならないのは、今期の届かない分をどうするか。原因が分かっても、今期の分は埋まらない。
2. なぜ、今期の分を先に決めるのか。→ 時間が過ぎるほど、打てる手が減る。原因は後でも調べられる。埋める手は今動かないと間に合わない。
3. なぜ、間に合うかがそこまで重いのか。→ 計画の数字は、事業部として約束した数字。埋まる分と埋まらない分が早く確定しないと、部として他で補うか、上に報告するかを決められない。
4. なぜ、部として決められる状態が要るのか。→ 部長は事業部全体の計画に責任を負う。一つの未達は、全体の中でどう扱うかを決める材料になる。
5. なぜ、それが返し方を決めるのか。→ 持ち込みを見る目的は、案の出来を採点することではない。今期の数字に対して、責任者と部が次に動ける状態にすること。問うのは、そこに要るもの。
支え：「乖離した実績と見込みをどうリカバリをしていくのか？という計画の話。穴をどう埋めるのか、それは可能なものなのか、ダメな場合はどうなるのか」「前倒しして何をするのか？という問いに繋がる」「指摘にとどめて本題に集中」
行き着いた所：持ち込みには「今、何を決める場か」がある。その決定に要るものを問う。大事でも、その決定に要らないものは、別の場に分ける。

### ケース10（立場：契約と交渉に責任を持つ人）
出発点：残りの点を詰めて出し直しを求めた返事に「突き放すのは違う」「残りの小さな点を解決すれば完了」「出口や合意形成に必要なステップとどうしてほしいか？を簡素に伝える」。
1. なぜ、突き放さないのか。→ 大筋は合意でき、残りは小さい。小さな残りのために全体を出し直させると、PM には何が通って何が残ったのかが見えなくなり、手戻りだけが増える。
2. なぜ、手戻りを避けるのか。→ 先方への回答には期限がある。このやり取りは、方針を固めて交渉に出るためのもの。
3. なぜ、「固めて交渉に出る」ためのやり取りなのか。→ 部長が PM の方針を見るのは、採点のためではない。会社として出す方針を、PM と合意するため。
4. なぜ、合意が要るのか。→ 交渉の席に着くのは PM。PM が腹に落ちていない方針は、席で崩れる。結果に責任を負うのは部長。
5. なぜ、それが返し方を決めるのか。→ 返事は、PM とこの件を完了まで運ぶやり取りの一部。完了まであと少しなら、残りと進め方を伝えるのが、完了に一番近い。
支え：「穴はあるものの大筋は合意できうるロジカルな内容提示」
行き着いた所：返事は、本人とその件を完了まで運ぶためのもの。出てきたものが完了からどれだけ離れているかで、返す中身と重さが決まる。

### 11/09「良さそう」（立場：スキルを部下に使わせる人）
出発点：「合格に類する返答を返さず、延々と指摘を繰り返すのでは」「問題がなければ『良さそう』など相手に次のステップに進めるプロセスは必要」。
1. なぜ、要るのか。→ 使う人は、上げてよい状態かを知りたくて使う。指摘が尽きない道具では、いつ上げてよいかが分からない。
2. なぜ、分からないと困るのか。→ 直すことに終わりがなくなり、直すこと自体が目的になる。仕事が前に進まない。
3. なぜ、前に進むことが要るのか。→ 仕事には期限と次の工程がある。スキルを通す目的は、役割の責任を果たした状態にして、次へ進むこと。
4. なぜ、スキルが終わりを示すのか。→ 部長はその場にいない。終わりを示せるのは、スキルの返事だけ。
支え：「これはあくまでスキルです。決定権はないことに注意」
行き着いた所：スキルは、「ここまで出来ていれば次へ進んでよい」を本人に示せなければ、道具として成り立たない。決定権は持たない。

### 11/09「一長一短」（立場：スキルを部下に使わせる人）
出発点：「書き方の決まりを遵守すると自分の返し方に寄る。ただ受け手目線で見ると良い点の評価や、課題点の見える化が弱くなるので一長一短」。
1. なぜ、受け手には、良い点の評価と課題の見える化があるほうが良いのか。→ 受け手は部長の頭の中を知らない。簡素な返事からは、何が認められ、何が残っているかを読み取れない。
2. なぜ、読み取れることが要るのか。→ スキルは部長がいない所で使われる。部長本人なら後で聞ける。スキルの返事は、それだけで本人が動けなければならない。
行き着いた所：スキルの返事は、部長の返し方の再現ではなく、部長がいなくても本人が動けるだけの中身を持つ。
注：一件の言葉から。本人は「一長一短」として、決めていない。

## 2. スキルに入れる本質（汎用の形）

### A. 何を問うか
その件で本人が成し遂げること（今、決めること）に対して、結果を左右するものを問う。資料に欠けがあるか、根拠が書かれているか、から問いを立てない。
- 元：ケース8、ケース7。
- 別の場面：ケース1（個々の不備ではなく、施策の型と対象が合っていないことを問う）。10/20 若手の初稿（未記載は触れず、方向性を話す）。10/20 予算の承認（根拠を問う。承認では、数字の確度が結果を左右する）。ケース6（本人「一歩前の目線でせき止めている」と認めた）。
- これで、本人の懸念「根拠を求めるパターンと求めないパターンが入り乱れる」は起きない。分けているのは場面の型ではなく、その件の結果を左右するか。

### B. どう返すか
返事は、本人とその件を完了まで運ぶためのもの。出てきたものが完了からどれだけ離れているかで、返す中身と重さが決まる。届いていれば、次へ進んでよいと示す。完了は出てきたもので決まる。本人の動き方（合意した目標を目指して動いたか）は別に見て、是正の対象にする。
- 元：ケース10、11/09「良さそう」、10/22 の言葉、11/10「ベストを目指した結果ならどんな状態でも認めて完了になる？そんなわけないだろ」。
- 別の場面：ケース1（遠く離れている。個々の点を見ない）。ケース2（離れているが、動き方は是正の対象ではない。方向性が見える状態に戻す）。採用条件の緩和（動き方が是正の対象）。ケース8（「悪くない」「より良いな、ぐらい」）。

### A と B の根
返事そのものを、目的から決める。目的は、本人がその件で役割の責任を果たした状態になり、次が変わること。採点ではない。

### 保留：部長がいなくても本人が動ける中身
一件の言葉からなので、本質としては置かない。B の中で、何が届いていて何が残っているかを本人が読み取れる返事にする、という範囲にとどめる。

## 3 の訂正（11/10、本人の指摘を受けて）

本人の言葉：「ボーダーが定義されておらず、欠けがないことを条件としたら、結果的に重箱の隅をつつくスキルのままじゃないのか？？これは全体として『いいのか』『悪いのか』の判断がまずいるだろ。それをどこでやっているのか、やる予定なのかを聞いている」

- 下の 3 は、全体の判断を、個々の点の答えを集めた結果として最後に置いていた。欠けが無いことが「届いている」の条件になり、指摘のとおり、重箱の隅をつつく形のまま。
- 今のスキルには、全体の判断が一つある。手順4 の最初の二択「狙いと内容が噛み合っている／いない」。ケース8 もケース10 も、スキルはここで「噛み合っている」と答えた。その後、この答えは使われず、条件を一つずつ当てる段に移り、欠けがあれば出し直しを求めた。
- 直す所：全体の判断は、今の場所で、個々の点より先に、単独でやる。変えるのは、その答えに後の扱いを従わせること。
  - 全体がいい：個々の点は、全体の判断を覆さない。「これを直せば完了」「より良くするなら」として伝える。出し直しは求めない。
  - 全体がわるい：個々の点は見ない。なぜ噛み合っていないかを返す（今と同じ）。
- 下の 3 の「変える所 2」（完了に届いている／いないを、条件を全部満たすかで決める）は取り下げる。「変える所 1」のふるい（結果が変わる／変わらない）は、全体がいいと出た後に、どの点を伝えるかを選ぶのに使う。

## 3. スキルにどう組み込むか

### 今の流れのどこで止まっているか
A も B も、考え方としてはスキルの中にある。動いていない理由は、流れの順番。今は、資料から気になる所を拾う → 一つずつ答える → 最後に、載せるものを絞る。拾う元が資料で、目的に照らすのは最後の一度だけ。その一度も、「根拠」「結論」「なぜ今か」などを、どの持ち込みにも載せてよい項目として並べた一覧に照らしている。

### 変える所は二つ。足すのではなく、順番を入れ替える
1. 問いを、目的の側から立てる（A）。
   - 手順3 の終わりに、「この件で本人が成し遂げること」と「それが完了と言える状態」を書く。元は、導いた責任と、この件の目的。今の受け入れ条件の具体は「評価に要る材料が揃っているか」という資料の出来で書かれている。ここを、その件の完了の状態に直す。
   - 手順4 の問いは、そこから立てる。読むときの確認項目（checks.md）は、読むための助けに下げる。気づきは、「これが違っていたら、この件の結果が変わる／変わらない」の二択を通ったものだけを問いにする。
   - 残った問いは、今と同じく、持ち込みごとに答えが二つしかない形に落として答える（届いている／いない、ある／ない、見合う／見合わない）。答えと理由を一文ずつ。決められないときは「今の材料で決められる／決められない」→「その事実がある／ない」で、本人に一つ尋ねる。ここは変えない。
2. 判断の終わりに、完了までの離れを決める（B）。
   - 手順4 の終わりに、全体を二択で決める。「どれだけ離れているか」という程度の問いにはしない（10/27 に本人と決めた「論点を、答えが二つしかない問いに落として答える」を崩さない。11/10 の初版は程度の問いにしていた）。
     - 完了と言える状態に、届いている／届いていない。
     - 届いていないなら、今の組み立てのまま残りを直せば届く／届かない。
     - 本人の動き方は別に、合意した目標を目指して動いた／最初から届く範囲に置いた。
   - 手順5 の返し方と、手順6 の返事は、この二つから決める。届いていれば、次へ進んでよいと伝える。最終決定は部長に残す。

### 外すもの
feedback.md の「返事に載せるもの」の一覧。A の基準一つに置き換える。

### 入れないもの
本人の言葉。ケースの結論（8% の根拠は問わない、原因は別口、など）。場面のファイルへの書き足し。

### 確かめ方（作った後）
設定を本人に確認済みのケース（6・7・8・9・10）で走らせる。見るのは、問う点と返す重さが本人と同じ向きか、本人が言わないことを言っていないか、返事を受けた本人が動けるか。役割の責任を果たしている持ち込みの新しいケースは、設定を本人に見せてから走らせる。
