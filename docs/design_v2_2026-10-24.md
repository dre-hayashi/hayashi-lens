# hayashi-lens v2 の設計（2026-10-24、テスト用）

## なぜ作り直すか
本人の問い「このスキル、私の思考ルーチンをトレースするためのフローチャートと、各ステップに対応した考え方や判断軸、本質や役割と責務の引き出し方をまとめてんのか？」に対し、現行版はそうなっていなかった。現行版は資料の種類で分けたファイル（重く置くもの、顔、場面、知識、十三の観点、絞り込み、書き方、監査）の束で、SKILL の手順は作業の順（開く、書く、絞る、書く、照らす）。段と判断軸が結びついておらず、実行のたびに組み立て直すため出力が不安定だった。
検証（docs/usage-log 参照、2026-10-24）では、監査を外しても返事は平均 3.6/5 で、問いの枠にそのまま乗る、判断の前の譲歩、判断を問いに置き換える、報告書の型、専門の見立てが途中で止まる、が条件を問わず出た。監査は平均で返事を少し悪くし、言い切っていた判断を消すことがあった。

本人の指示：「テスト用に別スキル作っていいから、ちゃんとできると思う形を考えて再設計とテストしてみて。今のスキルと比べられるように」。

## 形
- SKILL.md：入口とやらないこと。手順は「flow.md を段1から辿る」だけ。
- references/flow.md：本体。段1 受け取る、段2 土台を立てる、段3 責任の所在、段4 順に読む、段5 判断をまとめる、段6 返す。各段に、見るもの、当てる判断軸、役割の責任の引き出し方、引く知識、場面と席での現れ方。現行の scenes の中身は、各段の「場面ごとの現れ方」へ移した。checks の十三観点は段1〜4の「見るもの」へ、feedback の上げる・上げないは段5へ。
- references/axes.md：現行 core の、何のために見るか、何を見ているか、重く置くもの九、人に対して四。辿り方は flow へ移したので外した。文は現行のまま（本人確認済み）。
- references/reply.md：現行 style の合意内容、modes の媒体、出す前の読み返し三点。
- persona.md、roles.md、knowledge、glossary：現行のまま（参照先だけ直した）。
- 監査のサブエージェントは外した。代わりに、実行者自身の読み返しを三点（土台を落としていないか、言い切っているか、問いで逃がしていないか）に限った。

## 新しく足した段：持ち込まれた問いと前提そのもの（段2）
- 立場と役割：事業部長が、相談・報告・依頼を受ける席。
- 本人の言葉（場面をまたぐ）：10/20 三案「担当者としての結論・提言があってしかるべき、なければそれを問う」。10/20 優先順位「当初計画だ。土壇場で話が変わることがまずあり得ない」（三つから一つを選ぶ問いそのものを受けない）。10/20 採用条件「求人が集まらないって話じゃないじゃねぇか」（報告の前提が事実とずれている）。ケース1「合否以前の問題」。ケース2「依頼されているサイクルとエコノミーを見る…内容を見ていくと矛盾だらけだ」（依頼の枠より先に前提の矛盾）。ケース4「どこまで出すかの話ではなく、どのような権利体制なのか」。
- なぜの鎖：持ち込まれた問いに答えない → 問いが土台を外しているから → 外れた問いに答えても判断にならない（答えれば、ずれた前提を認めたことになる）→ 持ち込まれた問いは持ち込んだ人の見立ての結果で、見立てのずれが役割の責任の果たし方を表している → だから問いを土台へ戻して返すことが、本人に問う（core 人に対して）ことになる。
- 根拠の種別：本人の言葉（六場面）。鎖の最後の段は、core「資料は書いた人の思考の結果」（本人が認めた理解、10/20）に根がある。
- 線引き：問いが土台の上に立っているなら、問いに答える。資料に書かれていないことを前提に置いて疑わない。いつも置き直す、には振らない。

## 返事の形で足したもの（本人の価値ではなく、形の規則）
検証で判定役がどの条件にも共通して挙げた崩れ方への手当て：判断の前の譲歩や褒め言葉を置かない、判断を問いに置き換えない、報告書の型を使わない。本人の価値として書いていない。
文体はです・ますの話し言葉で通す。どの文体にするかは本人の価値ではなく、返事の一貫のための選択。

## テスト
現行版（監査あり）と v2 を、同じ場面、同じ問い、同じ隔離環境（リポジトリの外、スキルと持ち込みだけ）で実行し、記号を伏せた判定役が五つの観点（判断の筋、言い切り、流れ、声、中身）で採点する。場面はケース1〜5と、10/20 の対話の各場面十一件。判定役には本人の考え方を方向として渡し、字面の一致では評価させない。v2 はこの結果を見て場面向けに調整しない。
