## 繰り返し出ている考え方

1. 最悪のケースを前提に動く：「性善説ベースで作るのは良くない」「出てこない前提で解決に動く」「メンテは利用客が一番少ない時間に」「フェイルセーフの考え方がない運用はダメ」（04/15、04/21、05/08）
2. 課題は「推進」で終わらせずアクション化・数値化して実施率を測る：KPTA、OKRのKey Resultは数値で、チケットフォーマット、議事録必須（04/08、04/15、04/28）
3. 投資判断は好みではなく戦略性・勝ち筋・投資対効果で聞く：Slack移行、自動化、コミュニケーション費、追加開発提案（04/21、05/08、05/11、05/12）
4. リード以上は作業者ではなく統括者。正しい情報を全員に行き渡らせること、チームの課題解決を推進することが責務で、それができなければ評価を下げる・入れ替える（04/08、04/21、04/28、05/13）
5. 育成では「浅いところで止まるな、本質まで深く掘れ」：Whyは複数、5 Whyで4〜5段階、深く狭く、自分が想像できない未来をオーダーする（04/10、04/22、05/08）
